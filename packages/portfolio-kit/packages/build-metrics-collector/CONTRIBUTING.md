# Contributing

1. Describe the metric, provenance invariant, adapter state, or accessibility behavior being changed.
2. Add a synthetic counter-example that fails before the fix.
3. Preserve versioned contracts and stable diagnostic meanings.
4. Run unit tests, compilation, installed CLI demo, store replay, and HTML checks.
5. Update the specification, view contract, changelog, and disclosure when relevant.

Do not commit real credentials, private build logs, customer data, personal productivity records, or internal infrastructure details. Metrics should measure the work system, not rank individuals without context and consent.
